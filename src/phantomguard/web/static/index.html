START HERE / FOUR SMALL STEPS

From recording to reason.

  1. 01 / ESTABLISH A CLEAN RUN

    Choose a recording.

    Open Replay Lab, select a scene and leave attack on Clean. Start with 50–150 cycles, then Run. Jobs may queue or cool before processing. “Clean” means no injected attack; false alerts remain possible.

    Open the lab →
  2. 02 / CHANGE ONE VARIABLE

    Add a supported attack.

    Select T1–T4, an enabled capability and a seed. A2 repairs protocol structure; A3 adds plausible motion. T3 supports A3/A4 only. Use the same recording and seed to compare; support still depends on eligible material.

    Seeds and advanced options

    Seed fixes attacker randomness. Motion and translated replay options appear where supported. Cycle count limits displayed detection, not the attack's full-segment planning. A failed preparation is shown explicitly.

  3. 03 / FOLLOW A TRACK

    Play, pause, inspect.

    Use Play, Step or the timeline. Choose 2D or 3D before or after a run; both show the same cycle. Select a marker or object list entry to see its history and speed chart. 3D height is illustrative; no measured elevation or object class exists.

  4. 04 / READ THE EVIDENCE

    Separate flags from alerts.

    Green means not flagged. Amber flags have current reasons; red alerts can persist after a reason stops. Inspect reasons and calibrated score bounds, then Results for generated offline evaluation. Clip alerts are not an attack detection rate.

    Read generated results →
What this prototype can and cannot establish

CAN injection is simulated on recordings, with causal detector history and no labels entering inference. Seeking and themes reuse completed results. The clean false-alert target was not met in the supplied reports, and some eligible attacks evaded detection. Coordinate units, decoder layout and tick duration remain configurable assumptions. Cancel/Reset clears the displayed run and requests server cleanup.

A QUICK FIELD GUIDE

Three ways to inspect a claim.

  1. Run a clean clip. Green means the detector did not flag it. A clean recording can still produce a false alert.
  2. Add a supported CAN attack. The attacker emits ordinary encoded frames into the same decoding path. A supported request can lack eligible material.
  3. Inspect a verdict, then the matrix. A scene alert is different from finding the exact forged object. The offline evaluation is separate from your selected clip.

Capability & eligibility

A0 uses unrelated values and timing. A1 understands arrival timing and free slots. A2 also repairs protocol counts and counters. A3 adds plausible physics and continuity. A4 draws on recorded motion.

T3 is inherently A3/A4. T3 and T4 need moving tracks. Support is not a promise that a clip has free slots or eligible trajectories. An emitted attack can escape detection.

            Why an alert? Timing or continuity that differs from
            calibrated clean behavior supports an anomaly finding. Fusion can
            retain an alert after the current reason stops triggering.
          

          

            Why can a ghost be green? Genuine radar artifacts are still
            real sensor output. Static clutter and repeated motion are not
            automatically attacks. Green reports the detector’s decision only.
          

          

            Why can a forgery escape? A plausible trajectory can satisfy
            these checks. Scene detection and exact-object localization differ;
            this prototype cannot identify a human attacker or guarantee
            authenticity.
